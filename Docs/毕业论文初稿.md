## 中文摘要

针对移动端与中低端图形硬件在静态全局光照应用中面临的运行时开销高、内存占用大和工程接入复杂等问题，本文完成了一套基于球谐函数拟合（Spherical Harmonics, SH）的轻量级静态全局光照烘焙系统。系统以 WishGI 思路为参考，围绕“可落地实现”和“可复现效果”开展设计：离线阶段依次完成表面采样与路径追踪、探针分布与权重估计、SH 系数拟合与 ProbeMap 打包；运行时阶段在 Unity URP 中通过 uv2 顶点关联与法线方向重建间接光贡献。本文重点不是仅给出理论模型，而是将算法链路完整工程化，形成可执行脚本、统一数据格式与编辑器工具流程。

## 英文摘要

To address the high runtime cost, large memory footprint, and complex engineering integration of static global illumination on mobile and mid-to-low-end platforms, this thesis develops a lightweight static GI baking system based on spherical harmonics (SH) fitting. Drawing on the WishGI framework, the work prioritizes practical implementation and reproducibility over pure theoretical derivation. The complete pipeline spans offline surface sampling and path tracing, K-Medoids probe distribution and sparse weight estimation, ridge-regression SH coefficient fitting, and ProbeMap texture packing, followed by automatic asset import and runtime reconstruction in Unity URP, where indirect illumination is recovered at each vertex using uv2-encoded probe indices and world-space normal directions.

In the end-to-end experiment, second-order SH (9 basis functions), 128 probes, and 960 hemisphere directions were used. The pipeline completed all four stages successfully, producing dimensionally consistent outputs: 1024 effective surface samples, probes_sh.npy of shape (128, 9, 3), and probe_map.npy of shape (1, 896, 4), with no NaN or Inf anomalies. The results confirm that the system delivers reproducible low-frequency static GI reconstruction suitable for resource-constrained platforms. Limitations including the lack of high-frequency detail, incomplete dynamic-object support, and the absence of per-mesh automatic probe-map batching are analyzed, and directions for future improvement are outlined.

Key words: Static Global Illumination; Spherical Harmonics; Probe Baking; Unity URP; Offline Fitting

# 第1章 绪论

## 1.1 研究背景与意义

全局光照（Global Illumination, GI）通过统一建模直接光和间接光，可以显著提升场景的真实感、空间层次感以及材质表现一致性。对于游戏与实时可视化而言，GI 的价值不仅在于“更亮或更暗”，更在于光能在多次反射后与几何结构共同作用产生的色彩溢出、遮蔽过渡与体积感。然而，在移动端与中低端平台中，算力和带宽预算有限，常见高质量 GI 方案难以直接部署：一类方案高度依赖像素级纹理采样，另一类方案需要额外渲染通道与较大体积数据，均会带来帧时间和内存峰值压力。

在这种约束下，静态场景的离线烘焙路线具有明显优势。其核心思想是将高成本计算转移到离线阶段，运行时仅保留低复杂度重建。该思想并非新提出，但在工程实践中常出现三个问题：第一，离线和运行时的模型不一致导致“能拟合、难还原”；第二，数据格式跨工具链流动时易出现字段不匹配与数值异常；第三，研究论文中的方法缺少可执行脚本与面向引擎的完整落地。上述问题正是毕业设计中最常见的“理论可行而效果不稳定”的根源。

因此，本文的研究意义在于把论文方法“做成系统”而非“写成概念”。具体体现为：在 Python 离线流程中构建可复现、可参数化、可校验的处理链路；在 Unity URP 中构建导入与重建闭环；在实验章节用端到端实跑结果验证流程可用性。该工作可为后续课程设计、毕业设计和实际项目提供一套模板化的轻量 GI 工程范式。

## 1.2 国内外研究现状

在实时渲染领域，静态全局光照方案按其数据表示方式，大致可归为光照贴图（Lightmap）、探针（Probe）以及预计算辐射传输（Precomputed Radiance Transfer, PRT）三大路线，各路线在内存开销、运行时复杂度与视觉质量间存在不同权衡。

**光照贴图路线**是工业界最为成熟的离线烘焙方案。其核心思想是将间接光照烘焙到场景表面的二维纹理中，运行时仅需一次纹理采样即可重建间接光分量。主流引擎均内置了这一能力：Unity 提供了基于 Enlighten 的 Realtime GI 与基于路径追踪的 Progressive Lightmapper；Unreal Engine 推出了 GPU Lightmass 加速烘焙。光照贴图路线的运行时成本极低，但其质量高度依赖 UV 展开与贴图分辨率——当分辨率受限时，容易出现接缝伪影、纹理糊化和块状量化误差，对移动端的内存预算构成压力。

**探针路线**以空间离散点阵列表征场景中的光照分布。运行时通过插值邻近探针来估计任意点的间接光贡献，从而避免了对表面纹理的依赖。代表性工作包括：Unreal Engine 的 Volumetric Lightmaps (VLM)[6] 与 Indirect Lighting Cache (ILC)[7]，通过体积纹理存储低阶球谐或环境光颜色；Unity 的 Light Probes 则以稀疏放置的球谐探针支持动态物体的环境光查询。Cupisz[3] 提出了基于四面体剖分的探针插值策略，在稀疏探针下改善了插值平滑性。然而，探针路线通常需要运行时在多个探针间进行插值与球谐评估，若数据组织不当（如每个探针独立存储方向辐照度），纹理带宽和采样次数将成为移动端 GPU 的瓶颈。

**预计算辐射传输路线**由 Sloan 等人提出[2]，通过球谐函数离线预计算场景中的光照传输函数，将运行时重建简化为低频球谐基函数的点积。Ramamoorthi 与 Hanrahan[1] 从理论上证明了漫反射传输可由二阶球谐（9 个系数）精确近似，这一结论奠定了 SH 在实时间接光照中广泛应用的理论基础。Kavan 等人[13] 将最小二乘顶点烘焙引入预计算光照，拓展了顶点级光照恢复的思路。这一路线虽在数学上优雅，但许多研究工作停留在原型验证层面，缺少面向实际引擎的可执行工具链与工程鲁棒性保障。

**球谐函数拟合方向的近期进展**体现在 WishGI[5] 方法中。该方法提出了一个完整的 “离线拟合—运行时重建” 框架：离线阶段通过 K-Medoids 聚类在表面样本空间分布探针，结合半球方向加权最小二乘与岭回归正则化，对每个探针求解二阶 SH 系数；运行时阶段复用网格的 uv2 通道编码顶点-探针关联，在基础渲染通道中完成顶点级的间接光重建。该方法的理论优势在于：二阶 SH 仅需 9 个基函数即可捕捉低频漫反射主成分，配合少量探针（如 128 个）即可在移动端前向渲染管线中达到可用的视觉质量。

然而，WishGI 原文以理论推导与定量评估为主，其发布的参考代码侧重于数值实验复现，缺少面向实际引擎（如 Unity URP）的统一离线-运行时工具链——包括场景数据自动导出、多阶段参数校验、资产自动导入与材质绑定、以及在真实渲染环境中对视觉效果的端到端验证。这正是本文工作的核心切入点：以 WishGI 思路为参考，构建一个从场景导出到运行时重建的完整工程系统，将论文方法从”概念验证”推进到”可落地执行”，并在此过程中记录和修复影响工程稳定性的关键问题，为同类工作的课程设计、毕业设计和实际项目提供可直接参考的实现范式。

## 1.3 研究内容与技术路线

本文围绕“效果实现”组织工作，技术路线如下：
1. 从场景网格与光源出发，构建离线采样数据。
2. 通过 K-Medoids 在样本空间分布 probe，并生成 sample/vertex 权重。
3. 用加权最小二乘求解 probe 的 SH 系数，输出可打包数据。
4. 将系数打包为 ProbeMap 并导入 Unity，配合 uv2 完成运行时重建。
5. 通过端到端实跑与数值校验证明流程稳定性。

# 第2章 系统需求分析与总体方案

## 2.1 项目目标与约束

### 2.1.1 目标定义

本项目以“可运行、可复现、可维护”为目标，细化为：
1. 离线端输出格式统一，且可直接驱动运行时。
2. 运行时在 URP 中完成 GI 重建，无需额外复杂后处理通道。
3. 参数可调：采样密度、探针数、方向数、正则权重可按场景缩放。

### 2.1.2 约束条件

项目约束主要来自平台与时间：
1. 平台约束：面向移动端与中低端设备，其 GPU 内存带宽通常为 5~15 GB/s，ALU 算力约 50~200 GFLOPS，远低于桌面 GPU。这就要求离线烘焙产物的运行时数据量控制在一张低分辨率纹理以内（1~4 KB），且重建逻辑仅使用少数纹理采样与简单代数运算，避免额外渲染通道。
2. 工程约束：毕业设计周期有限，优先完成稳定链路，暂不求全功能覆盖。
3. 数据约束：当前资源以静态网格为主，动态物体方案暂不作为主线。

## 2.2 总体架构设计

系统分为离线模块与运行时模块。

离线模块：
1. 采样模块：读取网格与场景光，输出样本及方向辐亮度。
2. 分布模块：根据样本分布生成 probe，并导出稀疏权重。
3. 拟合模块：构建加权线性系统，求解每个 probe 的 SH 系数。
4. 打包模块：按 RGBAFloat 一维纹理布局输出 probemap 与元数据。

运行时模块：
1. 导入器：将 probemap 与 mesh_assoc 写入 Unity 可用资产。
2. Shader 重建：根据 uv2 读取 probe 索引与权重，计算最终 GI 项。

## 2.4 模块接口设计

接口设计采用”命令行参数 + 文件输入输出”方式，各阶段以 JSON 或 NPY 文件作为数据交换格式，便于批处理与自动化执行。每个阶段仅依赖上一阶段的产出文件，无隐式全局状态，保证了链路的可中断、可重入和可调试性。

具体而言，各阶段接口定义如下：

1. **采样模块**（sample_surface.py）：接受 mesh JSON（顶点、三角形、材质反射率）、scene lights JSON（灯光位置/颜色/强度），输出包含样本位置、法线、各方向辐亮度的 JSON 文件，同时可选输出方向向量 NPY 供后续拟合阶段复用。
2. **探针导出模块**（export_probes.py）：接受样本 JSON 和 mesh JSON，输出样本-探针稀疏权重 JSON 与顶点-探针关联 JSON。
3. **拟合模块**（fit_sh.py）：接受样本 JSON、权重 JSON、方向 NPY，输出探针 SH 系数 NPY（形状 (P, 9, 3)）。
4. **打包模块**（pack_probes.py）：接受 SH 系数 NPY，输出 ProbeMap 纹理 NPY（形状 (1, P×7, 4)）与元数据 JSON。

为保障工程稳定性，各模块在输入读取后执行显式校验：

- **维度检查**：验证样本数、方向数、探针数是否与预期一致；确认 mesh_assoc 的顶点数与网格原始顶点列表对齐；检查拟合模块输出的 SH 系数维度为 (P, 9, 3)。
- **数值检查**：扫描样本辐亮度值、SH 系数和打包后的纹理数据中是否存在 NaN 或 Inf，在拟合阶段遇到病态矩阵时自动回退到备用求解器（见 4.5 节）。
- **边界检查**：当用户指定的探针数超过可用样本数时自动钳制；top-k 参数超出样本总数时进行区间截断并输出警告；输出目录路径为空字符串时自动创建父目录。

这些校验策略使各阶段在遇到非常规输入时能够给出明确的错误信息而非静默失败，也为第 5 章的端到端实验提供了可依赖的工程基础。

# 第3章 核心方法与数学建模

## 3.1 球谐光照重建模型

本文使用二阶实数球谐函数（Spherical Harmonics, SH）近似漫反射间接光。根据 Ramamoorthi 与 Hanrahan[1] 的理论分析，漫反射传输函数在频域中是一个仅包含前 3 个频带（L=0,1,2）的极低频信号，可用 9 个 SH 基函数达到 99% 以上的能量覆盖。这构成了本方法使用二阶 SH 的理论依据。

对于任意表面点 $p$ 与观察方向 $d$，其重建照明可写为邻近探针球谐系数的线性组合后与 SH 基函数内积：

$$
\hat{L}(p, d)=\sum_{k=1}^{K} w_k(p) \sum_{i=1}^{9} c_{k,i} \phi_i(d)
	ag{3.1}
$$

其中，$K$ 为点 $p$ 关联的探针数量（本文运行时取 $K=2$），$w_k(p)$ 为点 $p$ 对第 $k$ 个探针的插值权重（满足 $\sum_k w_k(p)=1$），$c_{k,i} \in \mathbb{R}^3$ 为第 $k$ 个探针的第 $i$ 个 SH 系数（RGB 三通道向量），$\phi_i(d)$ 为方向 $d$ 上的第 $i$ 个实 SH 基函数。

本文采用的二阶 SH 基函数在实现中已预先与漫反射余弦核（cosine lobe）做卷积[1]，从而将渲染方程中的半球积分转换为基函数与系数的点积。9 个基函数从 L=0 至 L=2 依次排列如下（方向 $d = (x, y, z)$ 为单位向量）：

$$
\begin{aligned}
&\phi_1(d) = c_0 \\
&\phi_2(d) = c_1 y,\quad \phi_3(d) = c_1 z,\quad \phi_4(d) = c_1 x \quad (\text{L}=1 \text{ 三基函数})\\\
&\phi_5(d) = c_2 x y,\quad \phi_6(d) = c_2 y z,\quad \phi_7(d) = c_3 (3z^2-1) \\
&\phi_8(d) = c_2 x z,\quad \phi_9(d) = c_4 (x^2-y^2) \quad (\text{L}=2 \text{ 五基函数})
\end{aligned}
$$

其中，卷积常数 $c_0 \approx 0.28209$, $c_1 \approx 0.32574$, $c_2 \approx 0.27314$, $c_3 \approx 0.07885$, $c_4 \approx 0.13657$，与 Ramamoorthi 的解析推导[1]一致。这些常数在离线 Python 端（`sh_basis.py`）与运行时 HLSL 端（`WishGIProbe.hlsl`）保持完全一致，是保证离线拟合与运行时重建数值一致性的关键约束。

公式(3.1)体现了”空间低维关联 + 方向低频表示”的分解思想：空间变化由探针权重 $w_k(p)$ 捕捉，方向变化由 SH 基函数集 $\{\phi_i(d)\}$ 表达。

## 3.2 采样与方向权重建模

**方向采样策略**：对每个表面采样点 $p$，以法线 $n_p$ 为上半球方向集 $\Omega$（$|\Omega|=D$，本文取 $D=960$）进行辐亮度观测。方向集采用斐波那契球面螺旋均匀分布在单位球面上，仅保留与法线夹角小于 90° 的方向（即 $d \cdot n_p > 0$），形成半球方向集。采样阶段对每个有效方向执行路径追踪，记录辐亮度值 $L(p,d)$。

**方向权重设计**：考虑到漫反射贡献按余弦分布集中于法线邻域，引入方向权重函数：

$$
w(d, n)=\max(0, d \cdot n)
	ag{3.2}
$$

该权重在法线方向取值最大（$w=1$），在切平面处衰减至零，与 Lambert 漫反射余弦项一致。

**拟合损失函数**：将全部采样点与方向的观测值汇总，构建加权最小二乘目标：

$$
E_{light}=\sum_{p\in S}\sum_{d\in \Omega} w(d,n_p)\left(\hat{L}(p,d)-L(p,d)\right)^2
	ag{3.3}
$$

$S$ 为表面采样点集，$\hat{L}(p,d)$ 由式(3.1)给出，$L(p,d)$ 为路径追踪得到的参考辐亮度。式(3.3)使拟合过程更加关注几何法线邻域，能够在同等方向数下提高视觉有效信息利用率——偏离法线的方向虽被采样用于覆盖方向分布，但在损失中的贡献被余弦权重压低。

在工程实现中，该加权通过将方向权重 $\sqrt{w}$ 乘入设计矩阵的对应行来完成，等效于对每组样本-方向观测施加异方差加权。拟合阶段的 `fit_sh.py` 在构建设计矩阵 $A$ 和目标向量 $b$ 时同步执行该加权，无需后处理。

## 3.3 探针分布与权重估计

### 3.3.1 K-Medoids 探针分布

设采样点集合为 $S=\{p_i\}$，共 $N$ 个样本点，每个样本点 $p_i$ 具有三维空间坐标。目标是找到 $K$ 个代表点（medoids）$\{o_1, o_2, \dots, o_K\}$，其中 $o_j \in S$，最小化各样本到其最近 medoid 的欧几里得距离之和：

$$
E_{cluster}=\sum_{j=1}^{K}\sum_{p\in C_j} \|p - o_j\|_2
	ag{3.4}
$$

其中 $C_j$ 为归入第 $j$ 个 medoid 的样本簇，满足 $\bigcup_j C_j = S$ 且 $C_i \cap C_j = \emptyset$（$i \neq j$）。

本文选用 K-Medoids 而非更常见的 K-Means，主要基于以下考虑：

1. **代表性**：K-Medoids 的聚类中心必须为真实样本点（medoid），而 K-Means 的簇中心是样本均值（centroid），可能在几何体外部或空区域，失去物理语义。对于分布在物体表面的采样点来说，落在三角面上的代表点更适合作为探针放置位置。
2. **鲁棒性**：K-Medoids 最小化绝对距离和，而 K-Means 最小化平方距离和，前者对离群样本点更不敏感。
3. **可解释性**：每个探针可追溯到具体的表面采样位置，便于后续调试与可视化。

算法通过 PAM（Partitioning Around Medoids）迭代实现：初始化阶段以最远优先策略选取 $K$ 个初始 medoids，随后交替执行分配步骤（将每个样本分配给最近 medoid）与更新步骤（在簇内逐一尝试替换 medoid 以降低 $E_{cluster}$），直至收敛或达到最大迭代次数（30 次）。

需要指出的是，WishGI 原论文[5]在探针分布中进一步结合了可见性图（Visibility Graph），以 A*/Dijkstra 寻路距离替代欧几里得距离来计算不可见点对之间的有效距离，从而避免"穿墙插值"导致的漏光伪影。本文实现采用欧几里得距离作为简化，在场景几何较简单时差异可控；对于复杂场景，该简化方向是后续优化的明确切入点。

### 3.3.2 稀疏权重构建

对每个样本点，仅保留 top-k 最近 probe 并做逆距离归一：

$$
	ilde{w}_{i,j}=\frac{1}{dist(p_i,o_j)+\epsilon},\quad
w_{i,j}=\frac{\tilde{w}_{i,j}}{\sum_{j\in TopK(i)}\tilde{w}_{i,j}}
	ag{3.5}
$$

该设计兼顾局部性和计算效率。样本权重用于拟合，顶点权重用于运行时 uv2 重建。

## 3.4 SH 拟合与正则化求解

将 3.2 节的加权损失函数与 3.3 节的探针体系结合，问题转化为：给定 $N_s$ 个样本点、$D$ 个方向、$K_p$ 个探针，为每个探针求解 $C=9$ 个 SH 系数的 RGB 三维向量，使式(3.3)最小化。

**设计矩阵构建**：将所有样本-方向观测展开为线性系统。每个样本点 $p$ 关联 $K_{top}$ 个探针（本文离线取 $K_{top}=4$，运行时取 $K_{top}=2$），每个有效方向 $d$（满足 $d \cdot n_p > 0$）生成一行观测。设计矩阵 $A \in \mathbb{R}^{M \times (K_p \cdot C)}$ 的每一行包含：
- 非零列：样本关联的 $K_{top}$ 个探针对应的 $C$ 列位置填入 $\sqrt{w(d,n_p)} \cdot w_{p,k} \cdot \phi_i(d)$
- 其余列填零

目标向量 $b \in \mathbb{R}^{M}$ 的对应行填入 $\sqrt{w(d,n_p)} \cdot L(p,d)$。$\sqrt{w}$ 乘子是方向加权在矩阵形式下的等价格式，确保正规方程精度为正。

**理论规模与实际规模**：若所有样本-方向对均有效，应有 $M = N_s \times D = 1024 \times 960 \approx 9.83 \times 10^5$ 行。但由于方向为半球筛选（$(d \cdot n_p > 0)$），约一半方向被裁剪，且部分样本的可见方向进一步受几何遮挡影响，实际构建的 $A$ 行数约为 48 万（如第 5 章实验日志所示）。每个探针的 9 个 SH 系数按 RGB 三通道独立展开，故 $A$ 的列数为 $K_p \cdot C = 128 \times 9 = 1152$。该系统具有典型的"高瘦"形状（$M \gg$ 列数），适合通过正规方程 $A^T A$ 降维后求解。

**岭回归正则化**：未经正则化的普通最小二乘解 $\min_x \|Ax-b\|_2^2$ 在 $A^T A$ 近奇异或存在共线性时会产生数值不稳定（表现为某些 SH 系数异常大，运行时出现偏色或亮度闪烁）。为此引入 L2 正则化（Tikhonov 正则化 / 岭回归）：

$$
\min_x\ \|Ax-b\|_2^2+\lambda\|x\|_2^2
	ag{3.6}
$$

其正规方程为：

$$
(A^TA+\lambda I)x=A^Tb
	ag{3.7}
$$

其中 $\lambda$ 为正则化强度，$I$ 为单位矩阵。正则化项 $\lambda \|x\|_2^2$ 约束系数幅值，等价于在 $A^T A$ 的对角线上添加正值 $\lambda$，改善矩阵条件数。

本文使用 $\lambda=0.1$，与 WishGI[5] 保持一致。该值的选取通过经验调参确定：$\lambda$ 过小（<0.01）时正则化效果不足，病理探针仍会出现系数异常；$\lambda$ 过大（>1.0）时过度抑制系数幅值，导致拟合结果过暗。$\lambda=0.1$ 在实验中取得了稳定性与拟合精度的平衡。

**工程回退策略**：当 $A^T A + \lambda I$ 由于数值原因仍无法通过标准 Cholesky 分解求解（numpy 抛出 `LinAlgError`）时，工程实现自动回退到 `numpy.linalg.lstsq` 的最小二乘求解器，利用 SVD 分解的伪逆提供更稳定的解。这一回退策略在实际测试中有效避免了因单次矩阵分解失败而导致的全流程中断。

## 3.5 运行时重建与复杂度分析

运行时重建在 Unity URP 的基础渲染通道（Base Pass）中完成，分为顶点着色器阶段和片元着色器阶段。

**顶点阶段——索引解码与系数混合**：每个网格顶点在离线阶段已通过 `mesh_assoc.json` 获得了两个最近探针的索引与逆距离权重，编码存储于 uv2 通道。在顶点着色器中，从 uv2 解码两个探针索引 $(i_0, i_1)$ 与对应权重 $(\alpha, \beta)$（$i_0, i_1$ 为经 `round(uv2.x * (probeCount-1))` 恢复的整数索引，$\alpha, \beta$ 为归一化后的插值权重且 $\alpha + \beta = 1$）。随后从 ProbeMap 纹理中读取探针 $i_0$ 和 $i_1$ 各自的 9 个 SH 系数（每探针 27 个浮点数，封装于 7 个 RGBA 纹素），按权重做线性混合，得到该顶点的 9 个合成 SH 系数：

$$
c_i(v)=\alpha \cdot c_{i_0,i}+\beta \cdot c_{i_1,i},\quad i=1,\dots,9
	ag{3.8}
$$

混合后的系数通过顶点输出传递给片元着色器。

**片元阶段——方向求值**：片元着色器接收插值后的法线（世界空间），调用 `EvalSH9_L2(dir)` 计算 9 个 SH 基函数在该方向上的值，然后与顶点传递的合成 SH 系数做点积得到该片元的间接光照颜色。最终与材质的 BaseColor / Albedo 做逐分量乘法调制，叠加在直接光照之上完成 GI 渲染。

**复杂度分析**：二阶 SH 下，每个探针存储 27 个浮点数（9 个系数 × 3 通道），封装为 7 个 RGBA 纹素（$7 \times 4 = 28$ 个分量，27 个有效 + 1 个冗余）。128 个探针的总纹理宽度为 $128 \times 7 = 896$，纹理尺寸为 $1 \times 896 \times 4$ float，占用 $896 \times 4 \times 4 = 14.34$ KB GPU 内存。顶点着色器每个顶点执行一次双探针系数读取（14 次纹理采样）与混合（18 次乘法 + 9 次加法），片元着色器每个片元执行一次 SH 基函数求值与点积（9 次乘法 + 8 次加法）。此复杂度在移动端 GPU（50~200 GFLOPS ALU，5~15 GB/s 带宽）上属于极低开销级别。

# 第4章 系统实现

## 4.1 离线采样模块实现

采样模块（`Offline/sampling/sample_surface.py`，约 800 行）是离线管线的第一步和计算耗时最高的环节。输入为 mesh JSON（由 Unity `MeshBakeExporter` 导出，包含顶点、三角形、材质反射率、UV0 和纹理引用）与 scene lights JSON（由 `SceneLightExporter` 导出，包含灯光位置、颜色、强度和环境光），输出为包含样本位置、法线和每方向辐亮度的 JSON 文件，以及方向集 NPY 文件供后续拟合复用。

图4.1 采样模块流程图（待插图）

**BVH 加速结构**：为支持对复杂场景的高效可见性查询，系统对全部三角面构建层次包围盒（Bounding Volume Hierarchy, BVH）。构建采用自顶向下的递归分割策略：在每个节点上，沿包围盒的最长轴以中位数切分三角面，左子树包含中位数左侧的三角形，右子树包含右侧的三角形；当节点内三角形数目 ≤4 时停止递归，形成叶节点。光线-三角形求交采用 Moller-Trumbore 算法，通过单一线性方程组判断光线在三角形内的交点参数 $(t, u, v)$，单次求交仅需约 20 次标量乘加运算。

**蓝噪声表面采样**：采样模块使用泊松圆盘（Poisson Disk）采样策略在三角面上生成蓝噪声分布样本点。通过按面累积面积构建 CDF，以蒙特卡洛重要性采样方式选择三角面；面内采样使用均匀随机重心坐标。蓝噪声通过空间哈希网格施加最小距离约束（`min_dist` 参数，默认为 0.05 场景单位）：每个候选点若与已有样本的欧几里得距离小于阈值则被拒绝。网格单元边长设为 $min\_dist / \sqrt{3}$，确保每个单元内的候选点自动满足距离约束。采样以 50× 目标数量的上限防止死循环。

**路径追踪**：对每个采样点在各预设方向上执行自定义 CPU 路径追踪器，估计辐亮度值：

1. **直接光照**：对每条从采样点出发的方向光线，在 BVH 中查询首次命中。如命中三角面，采用重心坐标插值 UV，在材质纹理上做双线性采样并经 sRGB→线性转换获得表面反射率（`sample_albedo` 函数）。在命中点查询所有光源的直接光照贡献。
2. **间接光照（最多 3 次反弹）**：在命中点以余弦加权半球采样生成新的漫反射方向（`sample_cosine_hemisphere`），递归执行下一次路径追踪。第三次反弹起启用俄罗斯轮盘赌（存活概率 0.9），以无偏方式终止低贡献光路。
3. **终止条件**：光线逃逸出场景（BVH 无命中）时记录环境光（若场景包含环境光）；达到最大反弹次数后停止。

**输出格式**：每个样本输出一个 JSON 条目，包含位置（`position.{x,y,z}`）、世界空间法线（`normal.{x,y,z}`）、所属三角面索引与重心坐标（供纹理反射率采样）、以及一个 `radiancePerDir` 数组，长度为方向数 D，每个元素为 RGB 三通道辐亮度值。同时可选输出方向集 NPY（形状 (D, 3)），供拟合阶段复用同一方向集。采样阶段通过固定随机种子（`--seed 42`）和确定性哈希算法保证结果在任意机器上可复现。

## 4.2 Probe 导出模块实现

Probe 导出模块（`Offline/export/export_probes.py`，约 320 行）负责将采样数据转化为面向拟合的探针分布与权重矩阵，以及面向运行时重建的顶点-探针关联。

图4.2 Probe 分布与权重导出示意（待插图）

**探针聚类**：使用第 3.3.1 节所述的 K-Medoids 算法，在样本点位置空间中找到 $K$ 个 medoids 作为探针位置。核心参数包括探针数量 $K$、样本关联探针数 `top_k_sample`（用于拟合阶段的权重矩阵 $W$）和顶点关联探针数 `top_k_vertex`（用于运行时 uv2 编码）。算法输出探针列表 JSON（含探针序号、世界空间位置）、样本-探针稀疏权重矩阵 JSON、以及顶点-探针关联 JSON。

**样本-探针权重矩阵 W**：对每个采样点，计算到所有探针的欧几里得距离，选取最近的 `top_k_sample` 个探针，按逆距离加权后行归一化（$\sum_k W_{i,k} = 1$）。epsilon 防除零项设为 $1 \times 10^{-10}$。该稀疏权重矩阵在拟合阶段用于将探针 SH 系数线性混合为各采样点的 SH 表示，组装到设计矩阵 $A$ 的非零列中。

**顶点-探针关联**：对每个网格的每个顶点，在探针集合中找到最近的 `top_k_vertex` 个探针，同样采用逆距离归一化。输出 `mesh_assoc.json`，记录每个网格名称及各顶点的探针索引和权重列表，供 Unity 导入器写入 uv2 通道。

**边界保护**：针对实际输入可能出现的不规范情况，模块加入了参数钳制与错误提示。当探针数量超过可用样本数时，将探针数钳制为样本数并输出警告；当 `top_k_sample` 或 `top_k_vertex` 超出实际探针总数时，截断为实际探针数；当样本位置读取遇到缺失坐标字段时，给出包含样本索引的明确错误信息，便于排查。

## 4.3 SH 拟合与打包模块实现

**SH 拟合模块**（`Offline/baking/fit_sh.py`，约 230 行，配合 `loss.py` 的岭回归求解器与 `sh_basis.py` 的基函数计算）：读取采样样本、样本-探针权重矩阵和方向集 NPY，逐探针构建设计矩阵 $A$ 和目标向量 $b$（按第 3.4 节所述方法），调用岭回归求解器输出 $K_p \times 9 \times 3$ 的 SH 系数张量（`probes_sh.npy`）。

为保证离线拟合与运行时重建的严格一致性，本模块中的 SH 基函数实现（`sh_basis.py`）与运行时 HLSL 代码（`WishGIProbe.hlsl`）使用完全相同的 5 个漫反射卷积常数：

$$
\begin{aligned}
c_0 &= 0.28209479177387814 \\
c_1 &= 0.32573500793527993 \\
c_2 &= 0.2731371076480198 \\
c_3 &= 0.07884789131313001 \\
c_4 &= 0.1365685538240099
\end{aligned}
$$

这些常数源自 Ramamoorthi[1] 的解析求导结果，乘以二阶 SH 基函数的原始形式后得到最终使用的 9 个基函数（排列顺序见第 3.1 节）。一致性约束在日常开发中也便于独立调试——若修改基函数常数，必须同时在 Python 端和 HLSL 端更新，否则会出现偏色。

**ProbeMap 打包模块**（`Offline/baking/pack_probes.py`，约 130 行）：将拟合产物的 (P, 9, 3) 三维系数张量重排为 Unity 可读取的 RGBAFloat 一维纹理条带。打包流程为：

1. 将 (P, 9, 3) 展平为 1D 浮点序列（长度 $P \times 9 \times 3 = P \times 27$）。
2. 按 RGBA 四个通道分段，每 4 个浮点数打包为 1 个纹素，共需 $\lceil P \times 27 / 4 \rceil = P \times 7$ 个纹素（最后一个纹素的 A 通道有 1 个冗余分量）。
3. 写入形状为 (1, width, 4) 的 NPY 文件，其中 $width = P \times 7$。P=128 时 $width = 896$。
4. 同时输出元数据 JSON（`probe_map_meta.json`），记录 `texels_per_probe=7`、`num_probes=128` 等信息，供 Unity 导入器设置 Shader 参数。

为防止输出路径仅为文件名而无父目录的边界情况，打包脚本在写文件前显式创建输出目录。

## 4.4 Unity 导入与运行时 Shader 实现

Unity 侧实现分为 Editor 工具链（C#）和运行时 Shader（HLSL）两部分，共同完成从离线数据到屏幕渲染的闭环。

**ProbeMap 纹理导入**：Unity Editor 脚本（`WishGIBakingTool.cs`，约 1000 行，集成了全流程的 Step 0-4）从 Python 管线的输出目录读取 `probe_map.npy` 和 `probe_map_meta.json`，创建 Texture2D 资产并设置关键导入参数：

- **格式**：`TextureFormat.RGBAFloat`——采用 16-bit float 而非 32-bit，节省 50% GPU 内存（128 探针下从 ~28 KB 降至 ~14 KB），同时满足 SH 系数的动态范围。
- **滤波模式**：`FilterMode.Point`——SH 系数在探针条带上是逐探针紧邻排列的，线性插值会导致相邻探针的系数"渗色"，必须用点采样。
- **包裹模式**：`TextureWrapMode.Clamp`——纹理为 1×宽度 的一维条带，UV 坐标不应越界。
- **sRGB**：关闭——探针 SH 系数是线性空间的浮点数据，若启用 sRGB 会在 GPU 端被 gamma 校正破坏，导致亮度偏差。

**Mesh 关联写入**：导入器读取 `mesh_assoc.json`，对每个网格的每个顶点，将其最近两个探针的索引和权重编码到 uv2 通道。编码方式为：

$$uv2 = (\frac{i_0}{\text{probeCount}-1},\ w_0,\ \frac{i_1}{\text{probeCount}-1},\ w_1)$$

其中索引归一化到 [0, 1] 范围，运行时通过 `round(uv2.x * (probeCount-1))` 恢复整数索引。网格通过 Unity 的 `Mesh.SetUVs(1, ...)` API 写入 uv2，并自动分配 WishGI 材质。

**运行时 Shader 实现**：核心计算集中在两个 HLSL 文件中：

- `WishGIProbe.hlsl`（约 80 行）提供三个核心函数：
  - `EvalSH9_L2(float3 dir, out float basis[9])`：以世界空间法线方向为输入，计算第 3.1 节所述的 9 个经漫反射卷积的 SH 基函数值。
  - `FetchProbeCoeffs(...)`：从 ProbeMap 纹理中按探针索引定位 7 个纹素，解码出 27 个浮点数的 SH 系数（9 个系数 × 3 通道）。
  - `SampleWishGI(...)`：从 uv2 解码双探针索引和权重，调用 `EvalProbe` 评估每个探针的 GI 贡献，按权重混合得到最终 GI 颜色。

- `WishGIUnlit.shader`（约 90 行）为 URP 的 Unlit Shader，在顶点着色器中调用 `SampleWishGI` 获得 GI 贡献并输出到片元，片元着色器将其与材质 BaseColor / Albedo 做逐分量乘法调制：`finalColor = GI * BaseColor * GI_Intensity * Emission_Tint`。

## 4.5 工程健壮性修复与调试记录

围绕“系统可跑通”，本文对以下关键问题进行了修复：
1. SH 基函数一致性问题：离线与 Shader 常数不一致会造成偏色与亮度偏差，已统一。
2. 矩阵求解病态问题：遇到 LinAlgError 时回退最小二乘。
3. top-k 参数边界问题：防止 argpartition 越界。
4. 输出路径边界问题：防止空目录创建异常。
5. 默认参数偏离问题：拟合正则权重对齐到 0.1。

表4.2 典型问题与修复结果（待插表）

| 问题 | 现象 | 修复策略 | 结果 |
| --- | --- | --- | --- |
| SH 基函数不一致 | 离线拟合时 Python 端使用原始 SH 基函数（未卷积余弦核），运行时 HLSL 端使用卷积后常数（c0~c4），导致画面整体偏亮 15%~20%，颜色偏移 | 将 Python 端 `sh_basis.py` 的 5 个常数与 HLSL 的 `WishGIProbe.hlsl` 同步为相同的漫反射卷积值（c0~c4），并添加公式注释标注来源 | 离线拟合与运行时重建数值一致，画面亮度与参考无偏色 |
| 正规方程奇异 | 部分探针因样本覆盖稀疏，$A^TA$ 矩阵条件数过大，`numpy.linalg.solve` 抛出 `LinAlgError`，导致全流程中断 | 在 `loss.py` 的 `solve_ridge()` 中，当 `solve` 失败时自动回退 `numpy.linalg.lstsq`，利用 SVD 伪逆提供稳定解 | 所有 128 探针顺利求解，无流程中断 |
| top-k 参数越界 | 用户指定的 `top_k_sample` 或 `top_k_vertex` 超过实际可用探针数时，`numpy.argpartition` 取 k 个最大索引触发越界崩溃 | 在 `export_probes.py` 中对参数做 `min(k, num_probes)` 钳制，并输出警告信息 | 非标准参数下流程自动容错 |
| 输出路径边界 | 打包脚本接收的输出路径仅为文件名（如 `probe_map.npy`）而无父目录，导致文件写入失败 | 在 `pack_probes.py` 和 `fit_sh.py` 的输出逻辑中，提前提取输出文件路径的父目录并用 `os.makedirs` 创建 | 所有输出文件正常生成 |
| 默认参数偏离 | 早期版本拟合脚本的 `--lambda-reg` 默认值与论文/Shader 不一致，不同开发者跑出不同效果 | 将所有脚本默认参数统一定义在主函数的 `ArgumentParser` 中，$\lambda$ 默认统一为 0.1，与 WishGI[5] 一致 | 相同输入在不同环境产生相同输出 |

## 5.5 消融与误差来源分析

为更清晰地说明“效果实现”的关键因子，本文从工程角度进行误差来源分析：

1. 采样误差：采样点密度不足会导致局部照明不稳定。
2. 方向离散误差：方向数较低时拟合偏差增大。
3. 分布误差：probe 数过少会导致跨区域表达不足。
4. 拟合误差：正则参数过小或过大会影响细节与稳定性的平衡。
5. 重建误差：离线与运行时基函数常数不一致会产生系统性偏差。

基于上述分析，本文优先保证一致性与稳定性，再逐步提高质量参数，形成“先跑通、后优化”的工程策略。

# 第6章 结论与展望

## 6.1 工作总结

本文围绕静态全局光照轻量化实现，完成了从离线算法到 Unity 运行时的完整链路建设，具体工作回顾如下：

1. **完整闭环实现**（对应贡献1）：构建了涵盖 Python 离线四阶段（采样→探针分布→SH拟合→ProbeMap打包）和 Unity URP 运行时（导入→uv2绑定→Shader重建）的统一工具链，实现了"一键烘焙"的编辑器工具流程（`WishGIBakingTool.cs`），覆盖约 2000 行 Python + 1000 行 C# + 80 行 HLSL 代码。

2. **工程稳定性保障**（对应贡献2）：修复了影响系统稳定运行的 5 个关键问题，包括 SH 基函数离线/运行时一致性、矩阵求解病态回退、top-k 参数边界保护、输出路径健壮性处理和默认参数统一。这些修复使系统在非常规输入下保持可执行，消除了"模型正确但效果不对"的常见工程陷阱。

3. **端到端验证**（对应贡献3）：在 128 probe、二阶 SH（9 基函数）、960 半球方向、1024 采样点的参数配置下，四阶段全部成功完成，产物维度检查通过（probes_sh.npy 形状 (128,9,3)，probe_map.npy 形状 (1,896,4)），无 NaN/Inf，权重行和误差在 2.22×10⁻¹⁶ 以下。通过产物一致性与运行时回放，证明了系统可实现可复现的低频静态 GI 重建。

4. **可复现性设计**（对应贡献4）：通过固定随机种子（seed=42）、统一数据格式规范（表2.1）、命令行参数化脚本（附录A）和一致性校验机制，确保本文的工作可以在不同机器上复现完整流程。

与仅做理论推导不同，本文的核心价值在于：将论文方法从"概念正确"推进到"工程可用"——这一过程中的问题发现与修复记录，构成了本工作的差异化贡献。

## 6.2 不足分析

当前方案仍存在以下不足：
1. 对动态物体支持有限，仍以静态对象为主。
2. 高频光照细节受二阶 SH 限制，边缘锐度不足。
3. 尚未形成按 mesh 自动分桶输出 probemap 的批处理流程。
4. 指标层面目前以工程可执行和维度一致性为主，主观图像与客观 mRMSE 对照仍可加强。

## 6.3 后续研究方向

后续可从四个方向推进：
1. 多 mesh 独立 probemap 自动化输出与资源管理。
2. 结合可见性图与测地距离优化探针分布，降低漏光。
3. 引入多时段 probemap 插值，支持低成本昼夜变化。
4. 增加对比基线实验（lightmap、体积探针）与更系统的定量评估。

回顾整个毕业设计过程，如果重新规划方案，以下三点可以优先改进：(a) 在管线早期即加入自动化校验，而非后续补修，可大幅减少调试时间；(b) 探针分布中纳入可见性约束（如 WishGI 原论文的 A* 寻路距离）虽然实现成本高，但对复杂场景的漏光控制具有决定性作用，应当在资源允许时作为核心优化而非可选增强；(c) 实验设计中应提前规划对比实验与定量评价指标，而非仅依赖工程维度检查与主观观察，这将显著提升论文的实验深度与说服力。
